# JEV 问题描述与判断标准

> 历史开发记录：反映该轮实现与验证，提及的开发验证脚本未随发布包提供。当前行为以 [项目 README](../README.md) 和 [原型说明](prototype.md) 为准。

模型对比的 JEV 请求将 `question` 内的“问题描述 / description”与“判断标准 / criteria”分开显示。description 是界面用语；原生请求仍使用 `instructions`，旧数组请求仍沿用已有字段，不新增 `description` 字段。

## 标准编辑

- Choice、Score 保留逐项编辑及原有展开规则。Noul 默认展开“是的判断标准”“否的判断标准”，支持只填写一侧。
- 未填写的输入仅作提示。没有编辑时，缺失、`null`、单侧、空对象及旧请求形态均原样保留；不为模板自动补业务标准。
- 编辑一侧只改该侧；显式清空文字标准会删除该侧，两侧均删除后省略可选 `criteria`。未知扩展字段保留。
- 结构化标准按叶子编辑，字符串、数字、布尔值保留各自类型，嵌套数组/对象及未编辑节点不变。只有点击“改用文字标准”才将当前侧显式替换为文字。
- 切题、切答案类型均保留各自草稿。匿名展示使用独立草稿，修改后隐藏原响应；错误显示在弹窗内并关联字段。重置只清空草稿，不修改已保存记录。
- 结果标准继续读取该次请求快照，完整请求与响应详情保持原结构。

## 契约依据

[TypeSafe Python SDK — Noul / NoulCriteria](https://docs.typesafe.ai/sdk/python/api/types/questions#typesafe-sdk-noulcriteria)：`criteria` 可省略或为 `null`，对象内 `true` / `false` 均可选；每侧描述允许字符串、对象、数组或 `null`。因此不能要求两侧必填，也不能把单侧请求判为无效。

导入资料含 60 道 Noul 题：15 道原生含双侧文字标准、45 道原生未提供。模板未缺失或丢弃标准，本次补全的是发现及编辑入口。

## 验证

- 新 Noul 数据回归 14 项：覆盖 42 请求 / 115 题的未编辑保真、单侧/空值/结构化/未知字段、实际发送、历史复用、匿名副本及重置。
- 原答案编辑回归 19 项；结果显示回归 24 项；运行与重置回归 5 项。旧“单侧标准必须报错”用例已依官方契约修正。
- 浏览器验证 C13 既有标准编辑、单侧清空、运行及结果快照；B09 无标准占位与多题切换；结构化标准数字/布尔值保型、匿名弹窗错误与焦点恢复。
- 桌面和 390px 手机检查通过，长字段标签无横向溢出。运行仍为本地 Mock。
